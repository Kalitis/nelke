# Plans C + D + E: Web, TUI, Telegram frontends

## Goal
Implement the three remaining frontends as thin adapters over the existing core, establishing reusable patterns so each frontend only handles I/O. All business logic stays in `core/`. LLM is mocked in unit tests; real-model calls behind `@pytest.mark.integration`.

## Architecture: a new shared services layer

The CLI currently carries business logic that doesn't belong in a frontend (`_build_session_agent`, `_resolve_review`, `_event_console`, the cycle wiring). To avoid 4× duplication across web/tui/telegram, extract the **frontend-agnostic wiring** into a new `core/services.py` that every adapter (including a later CLI refactor) can call. Frontends then only implement: streaming render, human-gate UI, and transport.

### `src/nelke/core/services.py` (new — ~180 lines)
Pure-logic wiring functions (no I/O library imports beyond what core already uses):

- `build_chat_session(settings, profile, *, frontend_name, callbacks) -> ChatSession`
  - Consolidates `cli._build_session_agent` + `_workspace_for`: creates db session tagged `frontend_name`, opens memory + builds index, builds the agent with the passed `on_token/on_tool/on_tool_result` callbacks. Returns a dataclass `(agent, db, session_id, memory)`.
- `run_task(text, settings, profile, *, frontend_name, callbacks) -> AgentResult`
  - Async helper: builds session, runs `agent.run`, persists usage, ends session. Callbacks optional (None = non-streaming).
- `run_cycle(objective, settings, profile, *, on_event, human_approve) -> CycleResult`
  - Consolidates `cli.improve` core: opens repo/git/db/gov, builds `CycleEngine` with the passed async `human_approve` callable and `on_event` sink, runs, returns result + usage. **No printing.**
- `resolve_review(settings, request_id, decision) -> ResolveResult`
  - Consolidates `cli._resolve_review`: finds request, resolves in db, on "approved" checks out main + merges the cycle branch + updates cycle; on "rejected" marks cycle rejected. Returns `(cycle, branch, status, error?)`. **No printing.** This makes the "unified review_requests row, first frontend wins" contract testable and shared (plan §77).
- `list_open_reviews(settings)`, `get_memory_overview(repo)`, `recall_memory(repo, query, top_k)` — thin read helpers used by all three frontends' memory/review browsers.

Dataclasses for results (`ChatSession`, `ResolveResult`) so frontends render without reaching into core internals.

**Note:** CLI is NOT refactored in this phase (out of scope, risks regressions). The new `services.py` is additive; CLI keeps working as-is. A later commit can migrate CLI onto it.

## Phase C — Web (`src/nelke/frontends/web.py` + `templates/` + `static/`)

**Stack:** FastAPI + Jinja2 + SSE (`sse-starlette` or hand-rolled `StreamingResponse` with `text/event-stream`). Uvicorn launcher. itsdangerous signed-cookie sessions (no DB-backed session store needed — the db already tracks sessions by id).

**Dependencies added:** `fastapi`, `uvicorn`, `jinja2`, `itsdangerous`, `sse-starlette`.

**Routes:**
- `GET /` — chat UI (Jinja2 template: input box, transcript div, memory sidebar, profile switcher).
- `POST /api/chat` — accepts `{text, profile?}`, returns a `StreamingResponse` SSE stream. Wraps `services.run_task` with an async generator that converts `on_token`/`on_tool`/`on_tool_result` callbacks into `data:` SSE events (`{"type":"token","text":...}`, `{"type":"tool",...}`, `{"type":"done","usage":...}`). Per-browser session via signed cookie → db `session_id`.
- `POST /api/improve` — accepts `{objective, auto_approve?}`. Runs `services.run_cycle` in a `BackgroundTask`; the async `human_approve` callable pushes a review request to an in-memory `dict[cycle_id] → Future` and awaits it.
- `GET /api/events/{cycle_id}` (SSE) — streams cycle events + the human-gate prompt to the browser.
- `POST /api/review/{request_id}` — `{decision: "approved"|"rejected"}` resolves the Future → completes `human_approve` → CycleEngine merges or keeps branch. First resolution wins.
- `GET /review/{id}` — human-gate page: shows diff + AI verdict, two buttons. JS POSTs to `/api/review/{id}`.
- `GET /memory` — memory browser: list files + click to read.
- `GET /api/profiles` — provider switcher data.

**`templates/`**: `base.html`, `index.html` (chat), `review.html` (gate), `memory.html`. **`static/`:** minimal `app.js` (EventSource for SSE, fetch for actions), `style.css`. No build step, no framework — plain JS per plan §81 ("thick client rejected; only SSE + minimal JS").

**Launcher:** `web()` in `main.py` calls `web.launch()` → `uvicorn.run(app, host, port)` with `NELKE_WEB_HOST`/`NELKE_WEB_PORT` env opts.

**Tests (`tests/test_web.py`, mocked LLM):**
- App constructed with a `FakeLLM` injected via dependency override.
- `POST /api/chat` returns SSE chunks; assert token events accumulate to the answer + a `done` event with usage.
- `GET /` returns 200 + chat UI marker.
- `POST /api/improve` then `/api/review/{id}` with `approved` → cycle merges (uses `tmp_repo` fixture + a fake governance). Reject → branch kept.
- `GET /memory` lists files.
- All assert `db.create_session` was tagged `"web"`.

## Phase D — TUI (`src/nelke/frontends/tui.py`)

**Stack:** Textual. Patterns from Co-Researcher (referenced in plan): `@work(exclusive=True)`, an `AppState` dataclass, `compose`/`on_mount`/worker threading.

**Dependencies added:** `textual`.

**Layout (single `NelkeTUI(App)`):**
- `Header()`, footer with keybindings.
- **Chat tab** (`TabbedContent`): transcript `RichLog` (streaming via `on_token` → `write`/`append`), tool-activity lines (dim, separate from answer), input `Input`. Enter submits; `Ctrl+C` cancels the running worker (Textual worker cancellation). Multi-turn continuity (`reset=False`).
- **Improve tab**: objective `Input`, a `RichLog` that streams cycle events live (events push as they happen via `on_event`), collapsible gate output. Review **modal** (`ModalScreen`): shows diff + AI verdict, `✓ Approve` / `✗ Reject` buttons resolving the modal → returns bool to the cycle's `human_approve`.
- **Memory tab**: `ListView` of memory files + a `RichLog` preview pane; recall `Input` that calls `services.recall_memory` and shows ranked hits.

**Threading model:** `agent.run` / cycle run inside `@work(exclusive=True)` workers; callbacks (`on_token`, `on_event`) use `self.call_from_thread(self.log.write, ...)` to marshal UI updates onto the Textual loop. The review `human_approve` is an async callable that `await ModalScreen` — clean integration with `CycleEngine`'s awaitable gate.

**Launcher:** `tui()` in `main.py` calls `tui.launch()` → `NelkeTUI().run()`.

**Tests (`tests/test_tui.py`):**
- Textual `run_test()` / `App.run_pilot` snapshot: compose renders all three tabs without exception.
- Structural only (no business logic): assert widgets exist, input→submit dispatches a worker.
- A focused unit test on a `build_tui_callbacks(log)` helper (marshals callbacks to a `RichLog`) with a `FakeLLM` — verifies tokens reach the log. No real Textual loop needed for this.
- Per plan acceptance: "frontend-structural tests only".

## Phase E — Telegram (`src/nelke/frontends/telegram_bot.py`)

**Stack:** aiogram 3.x (`Bot`, `Dispatcher`, `Router`, `F`).

**Dependencies added:** `aiogram`.

**Commands:**
- `/start` — greeting + help.
- `/chat <text>` — acks immediately ("🤔 working…"), runs `services.run_task` in an async task, streams the answer via **message edits** (throttle edits to ~1/2s; final edit posts the complete answer + usage). Profile from `NELKE_DEFAULT_PROFILE`.
- `/improve <objective>` — acks, runs `services.run_cycle` in a worker. Cycle events stream as message edits. When the human gate fires, the `human_approve` async callable sends an inline keyboard (`✅ Approve` / `❌ Reject`) with callback data `approve:{cycle_id}` / `reject:{cycle_id}`; it stores a `Future` in an in-memory map and awaits it.
- **Inline button callback** (`CallbackQuery` on `approve:`/`reject:`): resolves the Future → CycleEngine merges or keeps branch. Edits the message to show the outcome. Same unified `review_requests` row (first frontend to resolve wins).
- `/cancel` — cancels the running worker for that chat (aiogram task cancellation).
- `/memory` — list / recall (inline buttons or text).

**Token:** `NELKE_TELEGRAM_TOKEN` read from env via the existing `config.load_env_files()` (called at frontend import, same pattern as `cli.py`). No `config.py` change.

**Launcher:** `bot()` in `main.py` calls `telegram_bot.launch()` → builds `Bot(token=...)` + `Dispatcher`, registers the router, `await dp.start_polling(bot)`. Wrapped in `asyncio.run`. Clear error if token missing.

**Bot session per chat:** map `chat_id → session_id` (db-tagged `"telegram"`); each chat gets continuity within a `/chat` conversation.

**Tests (`tests/test_telegram.py`, mocked aiogram):**
- A `FakeBot`/`FakeCallbackQuery` capturing `send_message`/`edit_message_text`/`answer_callback_query` calls — no network.
- `/chat <text>`: assert immediate ack + final message contains the FakeLLM answer + usage.
- `/improve <objective>` then `approve` callback → cycle merges (FakeGovernance + `tmp_repo`); reject → branch kept.
- Cancellation: `/cancel` mid-run stops the worker.
- Assert db session tagged `"telegram"`.

1. **`pyproject.toml`**: add `fastapi`, `uvicorn`, `jinja2`, `itsdangerous`, `sse-starlette`, `textual`, `aiogram` to `[project.dependencies]` (textual/aiogram/fastapi are runtime deps for the frontends).
2. **`main.py`**: `web()`, `tui()`, `bot()` commands dispatch to the real launchers instead of `cli.launch(...)` (keep `cli.launch` as a fallback message, but wire the three to their modules). Add `_check_llm` to the launchers where a profile is needed.
3. **`src/nelke/__init__.py` `boot_check()`**: add imports of `nelke.frontends.web`, `tui`, `telegram_bot`, `core.services` so a broken import in any new module fails the rollback gate (the existing self-improve safety net).
